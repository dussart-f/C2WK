Objectifs

Configurer un server DHCP et recuperer des adresses ip dynamiquement dans un réseau complexe

Equipement nécesaire
  • 4 VPC
  • 3 router c3725
  • 3 switch
Consignes

Configurer R1 :
a - son interface dans le sous-réseau 10.0.0.0/24 ait l'addresse ip : 10.0.0.254

  • un server DHCP qui :
     - distribue des ip dans la range 192.168.1.10 - 192.168.1.50 pour le sous-réseau 192.168.1.0/24
     - distribue des ip dans la range 172.16.1.10 - 172.16.50.255 pour le sous-réseau 172.16.0.0/16

Configurer R2 :

  • il doit router les paquets du sous-réseau 192.168.1.0/24 vers 10.0.0.0/24 et inversement
  • son interface dans le sous-réseau 192.168.1.0/24 ait l'adresse ip : 192.168.1.254
  • son interface dans le sous-réseau 10.0.0.0/24 ait l'adresse ip : 10.0.0.2

Configurer R3 :

  • il doit router les paquets du sous-réseau 172.16.0.0/16 vers 10.0.0.0/24 et inversement
  • son interface dans le sous-réseau 172.16.0.0/16 ait l'adresse ip : 172.16.255.254
  • son interface dans le sous-réseau 10.0.0.0/24 ait l'adresse ip : 10.0.0.3

Configurer PC1:

  • doit se trouver dans le sous-réseau 192.168.1.0/24
  • doit recuperer son adresse ip en DHCP

Configurer PC2:

  • doit se trouver dans le sous-réseau 192.168.1.0/24
  • doit recuperer son adress ip en DHCP

Configurer PC3:

  • doit se trouver dans le sous-réseau 172.16.0.0/16
  • doit recuperer son adresse ip en DHCP

Configurer PC3:

  • doit se trouver dans le sous-réseau 172.16.0.0/16
  • doit recuperer son adress ip en DHCP
Evaluation
  • PC1, PC2, PC3 et PC4 doivent pouvoir se ping mutuellement
Rendu

Déposez un screenshot de votre topologie GNS3 montrant les adresses ip obtenues en DHCP par les PCs ainsi que le résultat du ping de PC1 vers PC3 (ou PC4) dans le dossier 9 - truth/ de votre dépôt git avant de faire votre demande de validation sur l'intranet.
