Objectifs

Controller quel reseau à acces a internet

Equipement nécesaire
  • 4 VPC
  • 3 router c3725
  • 3 switch
  • 1 NAT
Consignes

Configurer R1 :

  • il doit récuperer un address ip en DHCP pour son interfacce connecter au NAT
  • il doit router les paquets du sous-réseau 192.168.1.0/24 a internet
  • les permissions doivent être gerer dans la liste d'acces 10
  • son interface dans le sous-réseau 10.0.0.0/24 ait l'addresse ip : 10.0.0.254

Configurer R2 :

  • il doit router les paquets du sous-réseau 192.168.1.0/24 vers 10.0.0.0/24 et inversement
  • son interface dans le sous-reseau 192.168.1.0/24 ait l'adresse ip : 192.168.1.254
  • son interface dans le sous-reseau 10.0.0.0/24 ait l'adresse ip : 10.0.0.2

Configurer R3 :

  • il doit router les paquets du sous-réseau 172.16.0.0/16 vers 10.0.0.0/24 et inversement
  • son interface dans le sous-reseau 172.16.0.0/16 ait l'adresse ip : 172.16.255.254
  • son interface dans le sous-reseau 10.0.0.0/24 ait l'adresse ip : 10.0.0.3

Configurer PC1:

  • doit se trouver dans le sous-réseau 192.168.1.0/24
  • doit avoir comme addresse ip : 192.168.1.11

Configurer PC2:

  • doit se trouver dans le sous-réseau 192.168.1.0/24
  • doit avoir comme addresse ip : 192.168.1.12

Configurer PC3:

  • doit se trouver dans le sous-réseau 171.16.0.0/16
  • doit avoir comme addresse ip : 172.16.1.13

Configurer PC4:

  • doit se trouver dans le sous-réseau 172.16.0.0/16
  • doit avoir comme addresse ip : 172.16.1.14
Evaluation
  • R1, doit pouvoir ping internet sur 8.8.8.8
  • R2, R3 ne doivent pas pouvoir ping internet sur 8.8.8.8
  • PC1, PC2 doivent pouvoir ping internet sur 8.8.8.8
  • PC3, PC4 ne doivent pas pouvoir ping internet sur 8.8.8.8
  • PC1, PC2, PC3, PC4 doivent pouvoir se ping mutuellement
Rendu

Déposez un screenshot de votre topologie GNS3 montrant le résultat du ping de PC1 vers 8.8.8.8 (succès) et de PC3 vers 8.8.8.8 (échec) dans le dossier 6 - shackles/ de votre dépôt git avant de faire votre demande de validation sur l'intranet.
