Objectifs

Vous devez connecter et faire communiquer 4 machines dans 2 sous-réseaux différent
Pour cela en plus des 2 router vous allez devoir rajouter 2 switch pour permettre a plus de machine de se trouver sur le même sous-réseau

Pour le moment vous avez vu que des sous-reséau en /24
Dans cette étape vous aller voir des agrégations d'adresses différente (i.e. CIDR) et du coup des masques de sous-réseaux différents

Equipement nécesaire
  • 4 VPCs
  • 2 router c3725
  • 2 switch
Consignes

Configurer R1 :

  • il doit router les paquets du sous-réseau 192.168.1.0/16 vers 10.0.0.0/8 et inversement
  • son interface dans le sous-reseau 192.168.0.0/16 ait l'addresse ip : 192.168.255.254
  • son interface dans le sous-reseau 10.0.0.0/8 ait l'addresse ip : 10.1.1.1

Configurer R2 :

  • il doit router les paquets du sous-réseau 172.16.1.0/20 vers 10.0.0.0/8 et inversement
  • son interface dans le sous-reseau 172.16.0.0/20 ait l'adresse ip : 172.16.15.254
  • son interface dans le sous-reseau 10.0.0.0/8 ait l'adresse ip : 10.2.2.2

Configurer PC1:

  • doit se trouver dans le sous-reseau 192.168.0.0/16
  • doit avoir comme addresse ip : 192.168.1.10

Configurer PC2:

  • doit se trouver dans le sous-reseau 192.168.0.0/16
  • doit avoir comme addresse ip : 192.168.100.10

Configurer PC3:

  • doit se trouver dans le sous-reseau 172.16.0.0/20
  • doit avoir comme addresse ip : 172.16.1.10

Configurer PC4:

  • doit se trouver dans le sous-reseau 172.16.0.0/20
  • doit avoir comme addresse ip : 172.16.10.1
Evaluation
  • R1 doit pouvoir ping R2 sur son interface dans le sous-réseau 10.0.0.0/8 et inversement
  • PC1 doit pouvoir ping PC2, PC3, PC4 et inversement
Indices

La différence grossière entre un switch et un router :

  • un switch connecte plusieurs appareil pour former un réseau
  • un routeur connecte plusieurs réseaux entre eux et definit comment les paquets transitent de l'un vers l'autres

Dans le modèle OSI le switch et le router font partie de 2 couches différentes, respectivement la 2 et la 3.

Rendu

Déposez un screenshot de votre topologie GNS3 montrant le résultat du ping de PC1 vers PC3 (ou PC4) dans le dossier 3 - shadows/ de votre dépôt git avant de faire votre demande de validation sur l'intranet.
